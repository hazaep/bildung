# Mariposa Potencial

## Definición operativa

La Mariposa Potencial (u [[Bildung/Lab/codex/Ontología/Opcionalidad]] de Segundo Orden) es la **proyección no lineal de cuántos nuevos estados, caminos o posibilidades habilita un experimento exitoso**, incluyendo aquellos que hoy no pueden preverse.

No mide lo que el experimento **produce directamente**, sino lo que **desbloquea**: el árbol de opciones que nace después.

Es la métrica más distintivamente [[Bildung/Lab/codex/Ontología/Bildung]] para evaluar experimentos, precisamente porque captura lo que las métricas lineales (ROI, output, velocidad) no pueden ver.

## Pregunta clave

> Si este proyecto funciona, ¿qué podría ocurrir que hoy no puedo prever?

## ¿Por qué "mariposa"?

Por el efecto mariposa de la teoría del caos: pequeñas perturbaciones en condiciones iniciales pueden producir consecuencias enormes en sistemas [[Bildung/Lab/codex/Ontología/Complejidad|complejos]].

En Bildung, la mariposa no es una metáfora — es una **heurística de inversión**:

> Prefiero un experimento pequeño con enorme potencial de desbloqueo que un proyecto grande con resultado predecible.

## Diferencia con opcionalidad simple

| | Opcionalidad (1er orden) | Mariposa Potencial (2o orden) |
|---|---|---|
| **Mide** | Caminos abiertos hoy | Caminos que podrían abrirse mañana |
| **Es** | Conocida, enumerable | Desconocida, requiere imaginación estructural |
| **Ejemplo** | "Aprender Docker me permite desplegar en servidores" | "Docker me llevó a orquestación, que me llevó a arquitectura distribuida, que me llevó a..." |

## Indicadores de alta Mariposa Potencial

Un experimento tiene alta Mariposa Potencial cuando:

1. **Es fundacional**: otras cosas dependen de ello (ej. [[Bildung/Lab/codex/Ontología/Normalización]] desbloquea todo el [[Bildung/Lab/codex/Ontología/Codex Bildung|Codex]])
2. **Es protocolo/puente**: conecta dos dominios previamente separados
3. **Es multiplicador**: reduce el coste de experimentos futuros
4. **Es genérico**: resuelve una clase de problemas, no una instancia
5. **Aumenta [[Bildung/Lab/codex/Ontología/Resolución Progresiva|resolución]]**: permite ver lo que antes era invisible
6. **Modifica o reestructura**: crea resolución dentro de alguna de las capas de Bildung

## Evaluación en la plantilla

La [[Plantilla de Evaluación Bildung]] dedica una sección completa a la Mariposa Potencial con tres preguntas:

1. **Si este proyecto funciona, ¿qué podría ocurrir que hoy no puedo prever?**
2. **¿Qué nueva puerta podría abrir?**
3. **¿Qué podría cambiar en el ecosistema completo?**

Estas preguntas son deliberadamente especulativas — obligan a modelar futuros posibles en lugar de solo calcular retornos predecibles.

## Ejemplo histórico (Bildung)

| Decisión        | Output directo               | Mariposa Potencial                                                                                                   |
| --------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Aprender Docker | Contenedores funcionales     | Despliegue → Servidores → Arquitectura distribuida → DevOps → Infraestructura como código → ...                      |
| Crear el Codex  | Definiciones normalizadas    | [[Bildung/Lab/codex/Ontología/Isomorfismo]] detectable → Patrones compilables → Gobernanza basada en ontología → ... |
| Esta Ontología  | Archivos .md interconectados | Lenguaje compartido → Documentación para outsiders → Grafo visual → Colaboración posible → ...                       |

## Anti-patrón

**Perseguir mariposas sin ejecutar**: fascinarse con el potencial de desbloqueo y nunca terminar el experimento que lo activa. La mariposa solo emerge si el experimento se completa.

**Ignorar mariposas**: evaluar todo por output inmediato. Es como rechazar una llave porque "solo abre una puerta" — sin considerar qué hay detrás de esa puerta.
