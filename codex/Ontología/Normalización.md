# Normalización

## Definición operativa

La normalización es el proceso de **convertir intuición, observación cruda o conocimiento tácito en una estructura explícita, reutilizable y conectable** — una definición, un modelo, un patrón, una regla — que puede integrarse en el [[Codex Bildung]] y ser utilizada por otras partes del ecosistema [[Bildung]].

Es el output principal de la [[Escuela 1 - Fundamentos del Arquitecto]], Módulo 1.4. Sin normalización, el [[Laboratorio Bildung|Laboratorio]] genera patrones que se pierden; con normalización, cada detección se convierte en infraestructura.

## Pregunta clave

> ¿Cómo convierto algo que sé en algo que puedo reutilizar?

## El pipeline de normalización

```
Intuición / Observación cruda
        ↓
Formulación explícita (poner en palabras)
        ↓
Definición operativa (no solo qué es, sino qué permite hacer)
        ↓
Conexión con el grafo existente (¿con qué otros conceptos se relaciona?)
        ↓
Inyección en el Codex (normalización completa)
        ↓
Disponible para ser usado por otras capas del sistema
```

## Qué se normaliza

| Entrada | Salida normalizada |
|---|---|
| "Siento que esto se conecta con aquello" | Un [[Isomorfismo]] documentado con evidencia multi-dominio |
| "Esto siempre me pasa" | Un patrón recurrente con condiciones de activación |
| "Este enfoque nunca funciona" | Un anti-patrón con contexto de fallo |
| "Creo que la clave es X" | Un concepto definido operativamente en la [[Ontología]] |
| "Esta decisión fue buena/mala" | Una regla de [[Gobernanza Adaptativa]] compilada |

## Propiedades de una buena normalización

1. **Operativa**: responde "¿qué puedo hacer con esto que antes no podía?"
2. **Acotada**: no intenta capturar toda la complejidad — captura la estructura suficiente para operar
3. **Conectable**: tiene bordes claros con otros conceptos (enlaces `[[ ]]`)
4. **Falsable**: puede demostrarse que es incorrecta o incompleta
5. **Versionable**: puede refinarse sin romper lo que depende de ella

## Por qué es difícil

La normalización es el punto de máxima [[Fricción Sistémica]] para mentes rizomáticas:

- El pensamiento rizomático es rápido, conectivo, multidimensional
- La normalización es lenta, lineal, reduce dimensionalidad
- **El desafío**: comprimir una red de conexiones en texto plano sin destruir su valor estructural

Es exactamente la fricción que mencionaste: *"poner en palabras lo que ya sé, para poder evaluarlo externamente, modelarlo e intervenirlo."*

## Anti-patrón

**Normalización prematura**: forzar una definición cuando el concepto aún es difuso. Produce definiciones vacías que no conectan con nada.

**Normalización infinita**: nunca declarar una definición como "suficientemente buena para operar". Todo es borrador para siempre. El sistema nunca se usa porque siempre se está definiendo.
